# DURF roadmap Gantt

A single standalone HTML page showing the six DURF themes across the 48-month
project, built on the [SURF Design System](https://surfnet.github.io/DesignSystem/).
The content comes from an Excel workbook that a project assistant can edit
without touching any code.

```
gantt.html                  the chart -- one self-contained file, ready to embed
index.html                  redirects to gantt.html?data=data/durf-roadmap.xlsx
data/durf-roadmap.xlsx      the source of truth; edit this
data/csv/*.csv              per-sheet CSV exports, regenerated by tools/build.py
tools/sync.py               pull the workbook from its share link, then build
tools/build.py              workbook -> CSVs + baked-in data in gantt.html
tools/seed_workbook.py      recreates the workbook from scratch (destructive)
tools/seed_data.py          the content transcribed from the DURF deck
```

The project runs **June 2026 – May 2030**. Project years are counted from the
start date, so Year 1 is Jun 2026 – May 2027 and the axis labels it `2026–27`.

## Editing the content

Open `data/durf-roadmap.xlsx`. The first sheet explains the rules; the short
version:

| Sheet | What it drives |
| --- | --- |
| `Themes` | The six theme rows, their names and their colours |
| `Activities` | Every bar on the chart |
| `Budget` | The budget table inside a theme's info panel |
| `Open questions` | The "what about …?" notes from the deck |
| `Settings` | Title, subtitle, intro, project start month, project length |

Extra columns are ignored, so you can keep working notes in the sheet — the
`needs:` columns, for instance — without them appearing on the chart.

`start_month` and `end_month` are **project months counted from 1**, not dates.
Month 1 maps to a calendar month via `start_year_month` in `Settings`
(currently `2026-06`, so month 1 is June 2026). `milestone_months` is a comma-separated list; each entry
becomes a diamond.

Do not rename the sheets or their header rows — the page looks them up by name.

## Getting your edits into the chart

**Preview, no tools needed.** Open `index.html` in a browser, click
**Load data…** and pick the `.xlsx` (or drag it onto the chart). The file is
parsed in the browser; nothing is uploaded anywhere.

**Publish.** Run `python3 tools/build.py` (needs `openpyxl`). It rewrites the
CSV exports and bakes the workbook into `index.html` between the
`DURF-DATA` markers, so the published page needs no companion files.

**Point the page at a file**, if you would rather not rebuild the HTML. Two ways,
and the URL wins if both are present:

```
gantt.html?data=data/durf-roadmap.xlsx          <- URL parameter
<div class="durf-app" id="durf-app" data-src="data/durf-roadmap.xlsx">
```

`index.html` is a one-line redirect to the first of those, so publishing the
whole folder and linking to it just works. The footer says which file was
loaded, or why it was not. A fetch that fails falls back to the baked-in copy,
so the page always renders.

This needs a real web server. Opened as `file://` the browser refuses to fetch
anything, so the page skips straight to the baked-in copy.

`?data=` only accepts files on the page's own origin, so a crafted link cannot
turn the page into a viewer for someone else's content. To allow other hosts,
name them on the `.durf-app` element — `data-allow-remote="surf.works.surf.nl"`,
comma-separated for several, or `"true"` for any host. `surf.works.surf.nl` is
allowed out of the box.

A Nextcloud or ownCloud share link (`…/s/<token>`) serves a web page rather
than the file, so the page appends `/download` for you. The format is decided
by sniffing the first bytes, not the file extension, so a link without an
`.xlsx` suffix still works.

The catch is CORS: the other host must send `Access-Control-Allow-Origin`, and
a Nextcloud public share does not. That is what the sync workflow below is for.

## Keeping the chart in step with a Nextcloud team folder

Run this from a machine that can open the share link — a laptop on the SURF or
university network:

```
python3 tools/sync.py
git add data gantt.html && git commit -m "Update roadmap" && git push
```

It downloads the workbook, checks it really is one, rebuilds, and tells you if
nothing changed. Pass a different link as an argument to override the default.

**Why this is not automated.** `.github/workflows/sync-roadmap.yml` does the
same thing on a runner, but its schedule is switched off: GitHub's runners
cannot open a connection to `surf.works.surf.nl` at all. Run 34484502000 timed
out on connect four times over eight minutes with no HTTP response, so this is
a network restriction on the SURF side, not a problem with the share. On a
schedule it would fail twelve times a day.

If that path is ever opened — SURF allowlisting GitHub's ranges, or a
self-hosted runner inside the network — uncomment the two `schedule` lines,
run the workflow by hand once to confirm the download step passes, and it
takes over. `ROADMAP_SHARE_URL` (Settings → Secrets and variables → Actions →
Variables) points it at a different share without editing the workflow.

The share must be reachable without a password, unexpired, and free of a
download limit. Nextcloud answers all three cases with an HTML page and a 200
status, so both `tools/sync.py` and the workflow check the file's magic bytes
and refuse rather than writing a password prompt over your data.

CSV also works on its own. Save any single sheet as CSV and load it — the page
recognises a sheet by its header row, and comma, semicolon and tab delimiters
are all detected, so a Dutch Excel export is fine.

## Embedding

The page is self-contained apart from one Google Fonts link, which degrades to
system fonts if it is blocked. Two ways in:

- **iframe** — `<iframe src="durf-roadmap.html" style="width:100%;height:900px;border:0"></iframe>`.
  Simplest, and fully isolated from the host page's CSS.
- **inline** — copy the `<style>` block, the `.durf-app` markup, the `<svg>`
  symbol and the two `<script>` blocks into your page. Every style is scoped to
  `.durf-app`, so nothing leaks into or out of the host page.

## Progressive disclosure

The chart shows one thing at a time, on purpose.

1. **At a glance** — six rows, one bar each, spanning the months that theme is
   active. The bar darkens where more of its activities run at once, so the busy
   stretches stand out without any reading.
2. **Open a theme** — its activities appear as their own bars. Recurring
   milestones (theme 6) draw as a thin rail with diamonds rather than a solid
   block, because they are dated moments, not continuous work. A single-date
   activity is just a diamond.
3. **Open an activity** — outcomes, timing, deliverable type, status, source
   links and any note about the underlying data.
4. **The `i` next to a theme** — goal, lead, partners, the budget table and the
   theme's open questions.

Supporting controls: a year zoom (which switches the axis from quarters to
months), deliverable-type filter chips, expand/collapse all, and a "now" marker.
Printing expands everything.

## Colours

| | Theme | Colour | |
| --- | --- | --- | --- |
| 1 | Governance | `#EE7628` | SURF orange |
| 2 | Metadata Quality | `#F6DA44` | SURF yellow |
| 3 | Full Text Capture | `#177ABF` | SURF blue |
| 4 | e-Depot Archiving | `#17A95D` | green |
| 5 | Distribution & Discovery | `#5C1B61` | dark purple |
| 6 | NL Research Portal | `#83201B` | dark red |

Themes 1–4 keep the deck's SURF accents. The deck reuses orange and yellow for
themes 5 and 6, which is ambiguous on a Gantt, so those two are separated by
**lightness** rather than hue. That matters: under red-green colour blindness
orange, yellow and red converge, and a mid-tone red for theme 6 sat only ΔE 9
from theme 1's orange. Going dark pushes the worst pair to ΔE 15.9 across
normal, protanopic, deuteranopic and tritanopic vision, with every pair at
ΔE 46 or more in normal vision.

Change any of them in the `colour` column of the `Themes` sheet. Bar text,
badges and markers are derived from whatever you set, and the derivation keeps
each hue while darkening it far enough to clear 4.5:1 — so the chart stays
readable, but a palette of your own choosing is worth re-checking for the same
kind of ambiguity.

## Resolved ambiguities from the source deck

Three activities had a timeline bar in the deck that disagreed with the months
written beside it. All three are now settled:

- Theme 4 — "Establish monitoring system for preservation status": months 12–38.
- Theme 4 — "Update and maintain URN:NBN resolver": months 12–18.
- Theme 5 — "Create monitoring system for tracking DURF content visibility":
  months 12–18.

The deck does not state a start date; June 2026 was confirmed separately and is
set in `Settings`.

## Browser support

Reading `.xlsx` in the browser uses `DecompressionStream`, available in Chrome
80+, Safari 16.4+ and Firefox 113+. Older browsers get a message telling them to
load a CSV instead; everything else on the page works regardless.
